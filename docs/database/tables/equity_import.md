# Table: equity_import

## Overview

| Property | Value |
|---|---|
| Table Name | `equity_import` |
| Purpose | One committed owner import of a normalized equities JSON file: its idempotency key, content hash, commit order and original payload. |
| Database | Application database (Cloudflare D1; `node:sqlite` as the portable engine) |
| Schema Section | 12. Equities library |
| Created By | `infra/migrations/0014_equities.sql` |
| Primary Key | `owner_id`, `import_id` |
| Storage | `WITHOUT ROWID` |
| Code | `packages/adapters/src/sql/equities.ts` |
| Update Strategy | Insert once per import; the same batch then restamps `committed_at` |
| Data Retention | Kept indefinitely; no code path deletes imports |

Each row is the manifest of one atomic owner import (ADR-0041). `createEquityRepository().commit` inserts it as the first statement of the import batch, and the `equity_record` rows, the relational projections and the `audit_log` row that follow are written only if it was inserted. It numbers the owner's imports (`commit_sequence`, the `ingestionVersion` of fact reads), stamps a strictly increasing `committed_at`, lets `findImport` answer idempotent replays, and keeps the original payload for download and re-import.

## Columns

| Column | Data Type | Nullable | Default | Description |
|---|---|---|---|---|
| `owner_id` | TEXT | No | - | The single owner's id (no owners table; every key starts with it, API-004). |
| `import_id` | TEXT | No | - | Import id, `eqimp_` plus 24 hex characters, generated by `createEquityService().import` (`IdGenerator.newId("eqimp")`). |
| `idempotency_key` | TEXT | No | - | The request's `Idempotency-Key` header (`idempotencyKeySchema`: 8-64 characters of `[A-Za-z0-9_-]`); a retry with the same key replays the stored result. |
| `content_sha256` | TEXT | No | - | Lowercase hex SHA-256 of `JSON.stringify` of the parsed `EquityImport`. Same key and hash is a replay (200); same key with another hash is `IDEMPOTENCY_KEY_REUSED` (409). |
| `committed_at` | TEXT | No | - | Commit instant, ISO-8601 UTC with milliseconds. Inserted as the service's receive time, then raised in the same batch to the latest of that time, the database clock and 1 ms after the owner's previous import, so it strictly increases per owner. `listFacts` compares it with `ingestionCutoff`; `listImports` orders by it. |
| `commit_sequence` | INTEGER | No | - | Per-owner import number, `max(commit_sequence) + 1` computed inside the insert. `getVersion` returns the maximum as the current `ingestionVersion`; `listFacts` drops facts whose contributing records came from a later import. |
| `coverage_note` | TEXT | No | - | The file's required `coverageNote` (1-1000 characters): the owner's statement of what the file covers. Shown in the import history. |
| `payload_json` | TEXT | No | - | The parsed import file as JSON (`equityImportSchema`, validated again on read by `getImportPayload`). Served by `GET /api/v1/equities/imports/:importId` for private backup and re-import. |
| `record_count` | INTEGER | No | - | Number of records in the file across all collections, 1-2,000 (`EQUITY_LIMITS.maxRecords`). Includes records the owner already held; those keep their original `import_id`. |

## Constraints

| Name | Type | Columns | Definition | Description |
|---|---|---|---|---|
| (unnamed) | PRIMARY KEY | `owner_id`, `import_id` | - | Identifies one import; `getImportPayload` reads by it and `equity_record.import_id` references it. |
| (unnamed) | UNIQUE | `owner_id`, `idempotency_key` | - | One import per idempotency key. `findImport` reads by it, and the insert's `ON CONFLICT (owner_id, idempotency_key) DO NOTHING` turns a concurrent retry into a batch that writes nothing. |

## Data Lifecycle

### Insert

`POST /api/v1/equities/imports` → `createEquityService().import` parses the file, checks its size, hash and idempotency key, and validates references, revision order and financial bases against the stored records (`importProblem`). `createEquityRepository().commit` then sends one D1 batch: this insert, `equity_record`, the projections, the `committed_at` restamp and an `audit_log` row (`equities.import`, detail `records:<n>`). The insert is an `INSERT … SELECT` that writes nothing when an incoming record id is stored with different content, an identifier `(scheme, value)` belongs to another issuer, a listing overlaps another episode of its `(venue_mic, symbol)`, or a metric `(metric_code, version)` has another id. Every later statement is guarded by `EXISTS` on this row, so the batch then writes nothing and the service answers 409 `CONFLICT`.

### Update

Only `committed_at`, once, by the restamp statement of the inserting batch (see the column). Nothing changes after the batch.

### Delete

Never: no code path deletes imports, and `equity_record.import_id` references them with `ON DELETE RESTRICT`. Rollback is a database restore ([equities library guide](../libraries/equities.md#operations)).

### Synchronization

Not applicable: imports are owner-uploaded files; there is no automatic provider ingestion.

### Retention

Kept indefinitely, one row per accepted import. `payload_json` is at most 750,000 bytes (`EQUITY_LIMITS.maxImportBytes`, enforced by the route's body limit and by the service).

## Notes

- The payload is stored twice: here and as the individual `equity_record` bodies. This copy is the restore source.
- A failed or conflicting import leaves no row and no audit entry.
- A different idempotency key makes a distinct import even when the records are identical; the stored records keep the import that first brought them.
