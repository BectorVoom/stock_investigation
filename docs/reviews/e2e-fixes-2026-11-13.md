# E2E fixes and independent review — 2026-11-13

Follow-up to [the initial E2E findings](administrator-login-e2e-2026-11-13.md).

## Changes

- Administrator sign-in now calls `location.reload()` through an injected UI
  callback. A link equal to the current hash URL only navigated within the
  document, leaving Cloudflare uncontacted. The regression test clicks Sign in
  and requires an actual document request while preserving the route.
- Currency, News navigation and Company-tab assertions now match the current
  documented presentation. They continue to check the value, unit, page order
  and Business overview rather than changing product behavior to old fixtures.
- Investigation tests check the supported answer prose and omission of a
  duplicate report preview. A schema-validated database read still requires
  exactly one generated audit report, the correct supported/unsupported
  statements, and its disclaimer. Malicious unsupported text is inspected in
  the evidence drawer and must stay literal, with no image or script execution.
- Notebook drag tests wait for the saved/read-back widget order before checking
  the target indices and reload persistence. The UI intentionally renders
  confirmed database state (ADR-0043), not an optimistic reorder.
- On macOS, Firefox gets an isolated test app-data cache through
  `CFFIXED_USER_HOME`. Each browser launch still uses Playwright's temporary
  profile. The workaround does not change the user's browser, profile, HOME,
  privacy grants, or installed executable. See [upstream issue 42768](https://github.com/microsoft/playwright/issues/42768);
  recheck with Firefox 158 / Playwright 1.65 or later.

The broader rerun uncovered two additional issues once earlier serial failures
were cleared:

- The rich-text selection toolbar was inserted in normal flow, moving the text
  during double-click selection. It now retains its layout space while hidden,
  with inactive controls inert and hidden from accessibility APIs. Browser tests
  require unchanged text coordinates and exact selected text; DOM tests require
  inactive formatting controls to be absent from the accessible UI.
- Firefox reported blocked eval from Zod schema initialization in a shared
  bundle, despite the entry point's early `jitless` configuration. Vite now maps
  exact bare `zod` imports to the browser-only configuration seam, which imports
  the unaliased `zod/v4` subpath and reexports its named/default API. Every browser
  schema depends on that seam, so configuration precedes construction after
  bundling too. Strict CSP remains unchanged and Node/Worker builds are unaffected.
  Initial session and rich-text browser tests require clean console/page errors.

Full Firefox coverage then exposed four test-driver assumptions that Chrome had
accepted:

- The Home wheel-drag released at y=1020 in a 900px viewport. The test now
  requires an actual wheel scroll, brings the target into view and asserts
  the drop is inside the viewport; exact save count, order and reload checks remain.
- Indicator SVG widths differ by ~0.00006 CSS pixels in Firefox. Dimension
  assertions use a 0.0005px tolerance rather than integer equality.
- The inline chart test now clicks the Shoelace combobox, not its host/label.
- The Task result test validates the accepted POST/202 and run identity, then
  its exact stored answer, instead of requiring a transient queue notice to
  remain after the runner has claimed the job.

The independent reviewer inspected these changes too, requested the explicit
wheel-scroll assertion, and found no remaining blocking issue after it was added.

No domain algorithm, database schema, vendor integration or hot path changed;
no new Lean model or benchmark is required for these UI/test fixes.

## Final WebKit viewer recovery fix

The first complete WebKit run exposed a genuine failed-import cache issue:
resetting the JavaScript promise did not refetch a failed ES module at the same
URL. The viewer now keeps its first normal lazy import but retries the trusted,
compiler-emitted same-origin root asset with a fresh query. A Vite virtual module
provides the compiled asset URL; the dynamic-import boundary validates exports.
The success promise stays shared, and no code/CSP bypass or eager viewer fetch
is introduced. The scope is a failed root asset, not a removed release asset or
an arbitrary failed dependency graph; a page reload may still be needed there.

The chart recovery test now intercepts query-bearing retries too and verifies
there is no eager request. Unit tests mock the fallible import boundary rather
than assuming an ES-module mock can reevaluate after a failed import. The
actual browser recovery test passed in all three engines. The chart suite's two
unconditional layout screenshots were also put behind its existing Chromium-only
screenshot policy: WebKit's screenshot tool injected inline styles that tripped
the otherwise-clean CSP gate. All geometry assertions still run in every engine;
no application console error is filtered.
